and its two reverification gaps (R1, R2) are fixed with regression tests (see
"Verification findings and fixes"), and all checks were rerun on the tested
OrbStack environment. Sign-off is the reviewer's call. Prepared 2026-09-25. Keep uncommitted with the other plans.

Read with `first-runnable-system.md` (Phase 2, §§7–8) and
`phase-2-implementation-handoff.md`, whose approved decisions this implements
unchanged: Docker (not an application) as the world runtime; fixed-size ext4 in
a Docker volume behind an explicitly authorized privileged helper; bounded
waiting with continuing jobs; POSIX message-queue creation disabled.

## Engineering findings during implementation

- **Container attach must not carry a request body.** The attach endpoint does
  not read one, so a `{}` body could reach the helper's stdin ahead of the seed
  archive (observed intermittently as tar "does not look like a tar archive").
  Attach now sends no body, and provisioning verifies the extracted seed against
  its manifest before `mkfs`.
- **Stopping the world races job inspection.** Container stop ends each job's
  stream, which prompted an inspection that recorded the stop's kill as an
  ordinary `exited 137`. The job table now stops interpreting engine state before
  the stop is requested; unfinished jobs end as `ended_with_world` and keep the
  engine's reported status as data.
- Python's locale coercion adds `LC_CTYPE` to its own `os.environ`; the
  environment check reads `/proc/self/environ` instead.

## Independent review (read-only, offline) and outcome

A separate review found no path that removes an unverified resource, runs the
privileged helper without authorization, or passes controller variables into a
world. Fixed from its findings:

- Admission depended on when the harness next looked: a finished job's held-open
  collector was only closed 5 s after its exit was *observed*, so admission could
  hinge on model latency. Unsettled jobs are now inspected every second.
- A start request with no answer made the job `uncertain` and released its slot,
  although the engine may have started it. It now stays `unconfirmed`, counted and
  inspected; `uncertain` (engine forgot the exec) also keeps its slot.
- `submit` is serialized, so duplicate IDs and admission cannot interleave.
- Releasing the world handle marked open output `complete`; it is now `failed`
  with a reason, and no inspection follows.
- `runControl` released its stream on errors, and an undrained reading counts as
  incomplete.
- `--json` output escapes C1 controls and bidirectional overrides.
- The capture helper checks the superblock options (`ro`, `norecovery`), not only
  the read-only bind; read-only volumes' options are checked after creation;
  the identity check requires `ro,norecovery`.
- An unverified stop no longer freezes job state.
- The startup reading now verifies memory, swap, CPU, and PID cgroup limits from
  inside; the engine check rejects any seccomp or AppArmor override.
- A helper whose engine stopped answering is no longer labelled as timed out.

Not changed, documented instead:

- Capture bounds (1536 bytes per inode) can be exceeded by ordinary worlds with
  many GNU long names or hard links, and paths over 4096 bytes are not indexed.
  Such archives are labelled incomplete, as the profile says; a later capture
  version could budget for them.
- Output frames of Docker stream type 3 (engine error text) are treated as a
  stream failure. Whether the engine sends them on exec/attach streams was not
  checked.

## Verification findings and fixes

`phase-2-verification-findings.md` reported six defects. Each is fixed and
covered by a regression test that reproduces the finding's scenario. The original
six tests were not run against the previous code; the five new R1/R2 tests were,
and each failed without its fix and passed with it:

1. **Dispatch after closure (P1).** `JobTable.quiesce()` refuses new submissions
   and waits for the one in progress; `stop()` and `close()` await it before
   stopping the container or closing the log. After its durable records, a
   submission rechecks closure with no await before the start request, and a
   refused start is recorded (`job.start_refused`). Tests hold the preparation
   hook, the durable record (including through a real `JsonlEventLog` closed in
   the backend's order), and an in-flight start, and cover the stop sequence.
   Integration: a submission racing `stop()` either never ran or ended with the
   world; on the tested engine it was refused before starting.
2. **Eviction re-enabled a job ID (P1).** Dispatch identity is separate from
   retained history: every ID prepared in the world is refused, including IDs
   loaded at start from the world log's durable `job.prepared` records, so the
   scope is the world lineage across controllers and restarts. Memory is bounded
   by the world log's size limit. An ID is spent even if its preparation fails.
   *Correction (R1):* this first fix did not bound memory as claimed: failed
   preparation records added IDs (and left unstarted executions) without adding
   to the log, so repeated failures grew without limit. After a pre-dispatch
   record fails, the table now refuses every later submission until the world is
   reviewed, so that path adds at most one ID and one unstarted execution.
   Tests: repeated hook failures, and a real `JsonlEventLog` that refuses every
   append followed by 1,000 more attempts (one execution created, none started).
3. **Stop-racing inspections (P2).** Inspections carry a stop epoch; an answer
   that arrives after a stop began is discarded, and the job ends as
   `ended_with_world` with the engine's status as data. Exits observed before the
   stop stay `exited`.
4. **Undrained capture stream reported complete (P2).** `runHelper` records
   whether the stream's end was observed; abandoning it at the drain deadline is
   a stream problem, so the archive is incomplete. Offline tests use a fake engine
   (missing EOF, stderr after exit, normal end).
   *Correction (R2):* any stream end still counted as drained, so a close without
   end-of-file at a frame boundary was accepted. Only end-of-file now counts, in
   all three stream consumers: helper runs (capture), job collectors (early close
   is `failed`, not `complete`), and harness readings (`runControl`, whose reading
   is then incomplete). Tests cover early close, stream error, missing end, and
   normal end.
5. **Negative modification times (P2).** GNU base-256 fields are decoded as
   signed two's complement for mtime only; sizes and other fields still reject
   negatives; range checks retained. Also checked against a Python `tarfile`
   GNU archive with `mtime = -1`.
6. **BOM stripped from names (P3).** Archive manifests and sensor listings decode
   names with `ignoreBOM: true`.

No targeted integration test forces an undrained capture stream on a real
engine; that case is covered offline only.

## Not verified or not done

- Docker Desktop and Linux Engine: unverified. Remote contexts: unsupported.
- Engine/application restart: not rerun (not authorized to restart the user's
  engine, which hosts unrelated workloads). Loss of loop bindings was simulated by
  detaching; Phase 0 verified persistence across a graceful OrbStack restart.
- A genuinely dirty filesystem from a crash was not produced; the refusal was
  tested by setting the superblock state with `debugfs`.
- Controller SIGKILL, watchdog, host sleep: Phase 4. Collectors live in the
  controller process; a controller crash loses them while jobs continue until the
  world is stopped. That is the interrupted-run contract, not a resumable state.
- No whole-descendant-tree kill is claimed or implemented.
- `perceiveHead` exists; observation packing, tool results for running jobs, and
  the tick loop are Phase 3.

## Notes for Phase 3

- `WorldBackend.submit(request, hooks)`: write `action.prepared` in
  `hooks.prepared`; if it throws, nothing starts. `DispatchRefusedError` and
  `JobAdmissionError` mean nothing ran. A returned snapshot may be `running`,
  `exited`, `unconfirmed`, or `uncertain`.
- Later job status belongs in subsequent observations (`sample().jobs`,
  `inspectJob`), never as a second tool result for the original call.
- The world log (`worlds/<id>/events.jsonl`) records lifecycle, helper runs, and
  job transitions with output byte counts and retained-output hashes. Retained
  output bytes are in `JobSnapshot`; the run log should store what the mind
  perceived.
- Sensor and signal readings are short execs as the world user: visible to the
  agent's `ps`, and they fail (reported unavailable) if the world's PID limit is
  exhausted.
